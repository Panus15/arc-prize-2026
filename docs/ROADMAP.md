## 1. เป้าหมาย

**ส่ง ARC-AGI-3 ให้รันได้จริง แล้วเขียน Paper Track ต่อยอด**

Paper Track **ยืนอิสระไม่ได้** — ต้องมี ARC-AGI-3 submission ที่ใช้งานได้ก่อน ลำดับจึงถูกบังคับ:
**code ก่อน → paper อ้างถึง code นั้น** (ที่มา: `competition-brief.md` §2, §8)

เหตุผลที่ยังคุ้มแม้เพดานความสามารถจะต่ำ:

| ข้อเท็จจริง | ผลต่อเรา |
|---|---|
| ผู้ชนะ Milestone #1 ได้ completion เฉลี่ย **8.3%** และ **0% ใน 2 จาก 25 เกม** | จบได้ 1 level สม่ำเสมอก็แข่งขันได้ |
| Paper คือ writeup ~1,500 คำ + notebook สาธารณะ | ไม่ใช่เปเปอร์วิชาการเต็มรูป |
| **5 ใน 6 เกณฑ์ให้คะแนน paper ไม่ขึ้นกับ leaderboard** | คะแนน code ต่ำไม่ปิดโอกาส |
| Bonus $375K เป็น **threshold ไม่ใช่อันดับ** | ไม่ต้องชนะใคร |

## 2. ข้อจำกัดที่กำหนดสถาปัตยกรรม

1. 🔴 **Internet ปิดตอน scoring** → เรียก LLM API ภายนอก **ส่งไม่ได้**
   เหลือ: โมเดล local ที่แพ็กไปกับ notebook / โปรแกรมล้วน / ลูกผสม
   **เราเลือกทาง "โปรแกรมล้วน" ไปก่อน** เพราะไม่ต้องใช้ GPU และเป็นมุมที่เขียนเปเปอร์ได้
2. 🔴 **ผู้เข้าแข่งเป็นผู้เยาว์** — เกณฑ์ไทยคือ 20 ปี ต้องมี parental consent
   และถ้าชนะ **ผู้ปกครองต้องลงนามภายใน 7 วัน** → เตรียมเอกสารล่วงหน้า
3. **ต้อง open source แบบ CC0 หรือ MIT-0** → repo นี้เป็น Public + MIT-0 แล้ว ✅
4. **Python 3.12** บังคับ ✅ · package manager `uv`
5. **คะแนนลงโทษ action เกินจำเป็น แต่ reasoning ฟรี** → คิดให้เยอะ กดให้น้อย

## 6. กติกาเหล็ก (สืบทอดจาก EcoSync)

> **ห้ามมโนตัวเลข — ทุกตัวเลขต้องวัดจริงและย้อนกลับไปหาที่มาได้**

บทเรียนจริงจากโครงการนี้ที่ยืนยันว่ากติกานี้จำเป็น:
- วิธีที่ได้ **88% บน mock** ได้แค่ **0.4% บนเกมจริง** — ถ้าไม่ตรวจกับของจริงก็จะเชื่อผิด
- เจอบั๊กที่ทำให้**ผลการเล่นไม่ซ้ำเดิมในแต่ละ process** ถ้าไม่เจอ ตัวเลขทุกตัวจะเชื่อถือไม่ได้
- ตัวเลข "greedy ได้ 0/3 ด่าน" ที่เคยรายงานไว้**ผิด** ค่าจริงคือ 1/3
