## 1. ช่องว่างที่ปิด

ตัวเลข "ต้อง probe 40–80 action" ใน `control-learning-curve.md` มาจาก trace ของผู้ชนะ
ซึ่ง **agent ตัวนั้นไม่ได้พยายามเรียนรู้ว่าปุ่มไหนทำอะไร มันพยายามเล่นให้ชนะ**
จึงเป็นการวัด *การสำรวจโดยบังเอิญ* ไม่ใช่ *การ probe อย่างตั้งใจ*

การเทียบที่ซื่อสัตย์ที่สุดคือรัน agent ของเรากับเกมสด ซึ่งยังทำไม่ได้
สิ่งที่ทำได้คือ **ใช้หลักฐานชุดเดียวกันแต่เปลี่ยนลำดับที่มันมาถึง** —
เรียง transition ที่บันทึกไว้ใหม่แบบสลับปุ่มเท่า ๆ กัน (แบบที่ตัว probe จะเห็น)
เทียบกับลำดับที่เกิดขึ้นจริง **ข้อมูลเดียวกัน learner เดียวกัน ต่างกันแค่ลำดับ**

## 3. 🔧 แก้ความเข้าใจเรื่องงบ probe

ตัวเลขสองชุดนี้วัดคนละคำถาม และเราเคยปนกัน:

| คำถาม | คำตอบ | ที่มา |
|---|---:|---|
| ต้องกี่ครั้งถึงได้ mapping **ที่ถูกต้อง 2 ทิศ** | **10–12** | เอกสารนี้ |
| ต้องกี่ครั้งถึงได้ความแม่น **เฉลี่ยทุก mapping ~81%** | **40–80** | `control-learning-curve.md` §2 |

**ผลต่อ agent จริง: ไม่ต้องรอถึง 80 action ก่อนลงมือ**
mapping 2 ทิศที่ถูกต้องพอจะเริ่มเดินได้ ใช้แค่ ~10 ครั้ง แล้วเรียนรู้ทิศที่เหลือระหว่างเล่น
การรอให้ครบ 4 ทิศอย่างมั่นใจคือสิ่งที่แพง ไม่ใช่การเริ่มเรียนรู้

## 4. ข้อจำกัด

- การเรียงลำดับใหม่เป็นการจำลอง ไม่ใช่การ probe จริง — transition แต่ละอันผูกกับสถานะเกม
  ณ ตอนนั้น การสลับลำดับจึงใช้ได้เฉพาะกับคำถาม "ปุ่มไหนทำอะไร" ไม่ใช่กับการเล่นทั้งเกม
- วัดจาก pass 0 ของแต่ละเกมเท่านั้น (17 เกมที่มีปุ่มทิศทาง)
- **ยังไม่เคยให้ agent ของเรา probe กับเกมสดจริง**
