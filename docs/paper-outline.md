## 2. มุมหลัก

**"ทำไม agent ที่ดูดีในห้องทดลองถึงตายในสนามจริง — วัดสี่ครั้งบน benchmark เดียวกัน"**

เราไม่แข่งด้วยคะแนน (2,936 ทีมทำ LLM agent, ผู้ชนะใช้ GPU, เราไม่มี)
แต่เรามีสิ่งที่แทบไม่มีใครมี: **ความล้มเหลวสี่ครั้งพร้อมการวัดทุกครั้ง**

| # | ที่ดูดี | ที่ล้มเหลว | แหล่ง |
|---|---|---|---|
| 1 | object-hash control learning บน mock — **88%** | board จริง — **0.4%** (10/2,276) | `real-game-validation.md` §2 |
| 2 | สัญญาณ "กระดานเปลี่ยน" ของ click policy | คลิกจริง — **91–100% เปลี่ยนอยู่แล้ว จึงไร้ค่า** | `click-validation.md` §2 |
| 3 | navigator บน mock สะอาด — **WIN 3/3** | mock ที่ calibrate ตาม noise จริง — **0/3** | `noise-validation.md` §3 |
| 4 | **overlap estimator บน mock ที่ calibrate แล้ว — WIN 3/3** | **board จริง — 55% (แย่กว่า centroid 79%)** | `estimator-comparison.md` §3 |

**ข้อ 4 คือข้อที่แรงที่สุด** เพราะพิสูจน์ว่า **การ calibrate simulator ด้วยสถิติที่วัดมาจริง ยังไม่พอ**

ทำไมมุมนี้เหมาะกับสถานะจริง:
1. **5 ใน 6 เกณฑ์ไม่ขึ้นกับ leaderboard** และ bonus เป็น threshold ไม่ใช่อันดับ
2. ผู้ชนะ Milestone #1 เองได้ completion **7.86%** และ **0% ใน 2/25 เกม** — เพดานต่ำมาก
3. **เรามีเครื่องมือให้คนอื่นใช้ต่อ** ไม่ใช่แค่บทเรียน

### ⚠️ มีหลักฐานบางส่วน

| ข้ออ้าง | ปัญหา |
|---|---|
| "probe อย่างตั้งใจเร็วกว่า" | เป็นการ**เรียงลำดับใหม่** ไม่ใช่ probe จริง — agent เราไม่เคยเลือกเอง |
| "ClickAgent ใช้ได้" | แก้สัญญาณตามข้อมูลจริงแล้ว แต่ยังทดสอบบน mock ที่เราเขียนเองเท่านั้น |
| "อ่านเลเยอร์สุดท้ายของ frame ถูก" | อ่านจาก engine ในเครื่อง ยังไม่ยืนยันกับ server |
