# ช่องว่างครั้งที่ 5 — รายการปุ่มที่ไม่เคยเปลี่ยน

> วัดเมื่อ **25 ก.ย. 2026** · ก่อนได้ไฟล์เกมจริงแม้แต่เกมเดียว
> ทำซ้ำ: คำสั่งท้ายไฟล์ · ตัวเก่าที่ล็อกไว้อยู่ที่ `arcagi3/navigator_v1.py` (= commit `dc949b4`)

## 1. เจอได้อย่างไร

ป้อนกระดานจริงที่บันทึกไว้ 25 เกม ผ่าน agent ตัวที่จะส่งจริงทีละเฟรม
(`scripts/replay_traces.py` — ดูว่า agent จะตัดสินใจอะไร แต่ไม่ได้เล่นจริง เพราะ action ในบันทึกเป็นของคนอื่น)
เกมเดินที่ **ค่ากลางเวลาต่อการตัดสินใจ 0.3 ms** เร็วผิดปกติ — agent ไม่ได้คิดอะไรเลย:

| เกม | ACTION5 ที่ตัวเก่ากด | ตัวใหม่ |
|---|---:|---:|
| ar25 | **99%** | 0% |
| cd82 | **99%** | 0% |
| cn04 | **99%** | 6% |
| g50t | **100%** | 0% |
| m0r0 | **99%** | 0% |
| re86 | **100%** | 6% |
| sp80 | **97%** | 10% |
| wa30 | **100%** | 0% |

**ทุกเกมเดินที่มี ACTION5 (8 จาก 17) ตัวเก่ากด ACTION5 แทบทุกตา** ไม่เคยลองปุ่มทิศทาง
จึงไม่มีทางเรียนปุ่มควบคุมได้ = **0 ด่านแน่นอนใน 8 เกม**

## 2. กลไก

| สิ่งที่ mock ของเราทำ | สิ่งที่ engine จริงทำ |
|---|---|
| ให้ ACTION5 **เฉพาะตอนยืนบนเป้าหมาย** และตัดทิศที่ติดกำแพงออก | ตั้ง `available_actions` **ครั้งเดียวตอนเริ่มเกม** แล้วส่งค่าเดิมทุกเฟรม (`ARCBaseGame.__init__`) |

docstring ของ mock เขียนไว้ด้วยซ้ำว่า *"The real API ships this per frame and it changes as the
game goes on"* — เป็นสมมติฐานที่เราเขียนเอง ไม่เคยตรวจ แล้ว navigator ก็พึ่งมันโดยไม่มีใครตั้งใจ
ผลพ่วงสามข้อ:

1. `if interact in available: press it` → ในเกมจริง **กดตลอดไป**
2. อ่านกำแพงจากรายการปุ่ม → ในเกมจริงทุกทิศ "เปิด" เสมอ ทุกสีถูกจดว่าเดินผ่านได้
   และ "ผ่านได้" ชนะ "ติดกำแพง" เสมอ → **เรียนกำแพงไม่ได้เลย**
3. จับการชนกำแพงจาก "กระดานไม่เปลี่ยนเลย" → บนกระดานจริง HUD ขยับทุกตา **ไม่เคยเกิด**

## 3. ทำให้เกิดซ้ำในการเล่นจริง (closed loop)

เพิ่ม `static_actions=True` ให้ mock ส่งรายการปุ่มคงที่แบบ engine จริง (ค่าเดิมยังเป็นแบบเก่า
เพื่อให้ตัวเลขที่ตีพิมพ์แล้วทำซ้ำได้) — ตัวเก่า **จาก 3/3 เหลือ 0/3 แม้บน mock ที่ไม่มี noise**
และกด ACTION5 **60 จาก 60 ครั้ง**

## 4. แก้อะไร — แต่ละข้อมาจากความล้มเหลวที่เจอระหว่างแก้

| # | แก้ | เพราะเจอว่า |
|---|---|---|
| 1 | กด interact เมื่อ **เพิ่งปรากฏ** เท่านั้น ถ้ามีตลอดให้กดหลังเดินไปยืนบนวัตถุ | กดตลอดไป |
| 2 | walker ไม่เลือก ACTION6 | adapter เปลี่ยนคลิกที่ไม่มีเป้าเป็นปุ่มอื่น แล้ว agent เรียนผลของปุ่มนั้นเป็นของคลิก |
| 3 | ตัดสินว่าก้าวสำเร็จจาก **ขอบหน้าหรือขอบหลังของ sprite เลื่อน** ไม่ใช่จุดศูนย์กลาง | ภาพเบลอทำให้ centroid อยู่ที่ปลายทางตั้งแต่ก่อนก้าว → **เป้าหมายถูกจดเป็นกำแพง** / และในด่านมีกำแพง จังหวะเบลอตรงกับรอบเดินพอดี → ชนกำแพงไม่รู้จบ |
| 4 | "ถึงแล้ว" = **เซลล์ใดของผู้เล่น** อยู่ในกรอบของเป้าหมาย **ที่กำลังมุ่งไป** | ยืนทับเป้าหมายแล้วเป้าหมายหายจากกระดาน (ถูกบัง) → ไม่รู้ว่าถึง เดินวน |
| 5 | ไม่เรียนรู้จากตาที่ข้ามด่าน | กระดานเปลี่ยนเป็นด่านใหม่ ผู้เล่นกลับจุดเริ่ม → อ่านเป็น "ก้าวไม่สำเร็จ" → เป้าหมายเพิ่งถึงกลายเป็นกำแพง |
| 6 | เดิน **6 ก้าวไม่เข้าใกล้ขึ้น → ทิ้งเป้าหมายนั้น** ในด่านนี้ | แถบ HUD อยู่นอกพื้นที่เดิน ถูกเลือกเป็นเป้าหมาย เดินชนขอบ ตัวตรวจคำทำนายล้างความรู้ทิ้ง 20 ครั้ง |

**ข้อ 6 ลองแบบอื่นก่อนแล้วผิด:** กรอง "วัตถุที่เปลี่ยนทุกตาไม่ว่ากดอะไร" (นาฬิกา) ออก —
แก้ HUD ได้ แต่ **เป้าหมายที่ขยับอยู่ก็ถูกกรองทิ้งไปด้วย** เทส ablation เดิมจับได้ทันที
จึงเปลี่ยนเป็นเกณฑ์ที่ไม่ต้องแยกสองอย่างนี้ออกจากกัน

## 5. ผลในการเล่นจริง (6 สนาม, 400 action)

```
arena                            random    v1 (frozen)       centroid        overlap     fallback *
quiet dynamic                2/3 in 400      3/3 in 40      3/3 in 40      3/3 in 40      3/3 in 40
quiet STATIC                 1/3 in 400     0/3 in 400      3/3 in 43      3/3 in 43      3/3 in 43
quiet STATIC scrambled       1/3 in 400     0/3 in 400      3/3 in 42      3/3 in 42      3/3 in 42
noisy dynamic                2/3 in 400     0/3 in 400      3/3 in 52      3/3 in 42      3/3 in 42
noisy STATIC                 1/3 in 400     0/3 in 400     0/3 in 400      3/3 in 67      3/3 in 67
noisy STATIC scrambled       1/3 in 400     0/3 in 400     3/3 in 132      3/3 in 64      3/3 in 64
```
\* walker ที่ submission ใช้ (`arcagi3.router.walker`)

- **ตัวเก่าชนะแค่สนามแรกที่เราเขียนเอง** แพ้ 0/3 ในอีกห้าสนาม
- ตัวที่ส่งจริงชนะทั้งหก รวมสนามที่ใกล้ของจริงที่สุด (noise + ปุ่มคงที่ + ปุ่มสลับ)
- เลือก `fallback`: ชนะทุกสนาม และบนกระดานจริงที่บันทึกไว้แม่น **77%** เทียบ centroid **79%**
  (`docs/estimator-comparison.md`) — ยอมเสีย 2 จุดเพื่อไม่ล้มในสนามที่มี noise

## 6. ⚠️ สิ่งที่ตารางนี้ **ไม่ได้** บอก

**ทั้งหกสนามยังเป็น mock ที่เราเขียนเอง** — ซึ่งเป็นสิ่งเดียวกับที่เปเปอร์บอกว่าหลอกเรามาแล้ว
ครั้งนี้เป็นครั้งที่ห้า สิ่งที่มีหลักฐานจากของจริงแล้วมีแค่ข้อ 1 ในตาราง §1
(พฤติกรรมบนกระดานจริงเปลี่ยนจริง) ส่วน "ผ่านด่านได้จริงไหม" **ยังไม่รู้** จนกว่าจะได้เกมจริง

## 7. เตรียมสำหรับ Kaggle ไปพร้อมกัน

| อะไร | เหตุผลที่วัดได้ |
|---|---|
| `MAX_ACTIONS` 400 → **2,000** | จากโค้ดคะแนนของ SDK: ด่านที่ไม่ผ่านได้ 0 ไม่ว่าใช้กี่ action → action เพิ่มมีแต่ได้ ราคาคือเวลา · agent ใช้ 4 ms/ตัดสินใจ (p99 25 ms) บนกระดานจริง · 100 เกม × 2,000 ≈ 1.7 ชม. จากเพดาน 12 |
| เก็บเฟรมย้อนหลังแค่ **32** | runner เก็บทุกเฟรมไม่ปล่อย วัดได้ **38–110 KB/เฟรม** → 2,000 × 55 เกม = **4–12 GB** · หน่วยความจำหมด = ทั้ง notebook ตาย ทุกเกมได้ 0 |
| error ใน policy → เสีย 1 action ไม่ใช่ทั้งเกม | error ใน `choose_action` ทำให้ thread ของเกมนั้นจบ ส่วนที่เหลือของเกมได้ 0 |

**ความทนทานบนกระดานจริง** (`replay_traces.py --passes 20`, ทั้ง 500 รอบ):

| | error | การตัดสินใจ | ค่ากลาง | p99 | สูงสุด |
|---|---:|---:|---:|---:|---:|
| ตัวเก่า (v1) | **0** / 500 | 69,182 | 1.3 ms | 13.9 ms | 45.2 ms |
| ตัวที่ส่ง | **0** / 500 | 69,182 | 4.1 ms | 25.4 ms | 57.9 ms |

ตัวที่ส่งช้ากว่าเพราะตอนนี้คิดจริง — ตัวเก่าใช้ 0.3 ms ในเกมที่มัน "คิด" แค่ว่าจะกด ACTION5
