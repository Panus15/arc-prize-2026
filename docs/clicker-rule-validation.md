# กฎการเรียนรู้ของ ClickAgent ตรวจกับผลลัพธ์จริง — ผลบวกครั้งแรก

> วัดเมื่อ 19 ก.ย. 2026 · repo commit `d3241ae`
> ทำซ้ำ: `cd agi3 && PYTHONPATH=. .venv/bin/python scripts/validate_clicker.py`

## 1. สิ่งที่ตรวจ (และไม่ได้ตรวจ)

`click-validation.md` ตรวจว่า **สัญญาณ** ไหนใช้ได้ (ผลคือ "กระดานเปลี่ยน" ไร้ค่า
ต้องใช้ "ผ่านด่าน") แล้วเราแก้น้ำหนักตามนั้น

เอกสารนี้ตรวจ **กฎที่ใช้น้ำหนักนั้น**: ถ้าป้อนผลลัพธ์ที่เกมจริงให้มาจริง ๆ
**กฎจะเลือกสีที่ถูกไหม**

> ⚠️ **ไม่ได้ตรวจตัว policy** — policy ไม่เคยเป็นคนเลือกคลิกเหล่านี้
> นี่คือการตรวจ *กฎการให้คะแนน* ไม่ใช่การเล่นเกม

## 3. ต้องใช้หลักฐานเท่าไหร่

| pass ที่ใช้ | เลือกถูก | เกมที่มีการผ่านด่านเลย |
|---:|---:|---:|
| 1 | 4/4 | **4 จาก 8** |
| 2 | 6/6 | 6 จาก 8 |
| 3 | **5/6** | 6 จาก 8 |
| 6 | 7/7 | 7 จาก 8 |

**ไม่เป็นเส้นตรง** — ที่ 3 pass มีหนึ่งเกมเลือกผิด แสดงว่ากฎนี้**ยังไม่เสถียรสมบูรณ์**
เมื่อหลักฐานน้อย

และข้อจำกัดที่สำคัญกว่า: **ยิ่งหลักฐานน้อย ยิ่งมีเกมที่ไม่เคยผ่านด่านเลย**
ที่ 1 pass มีเพียง 4 จาก 8 เกมที่มีอะไรให้เรียนรู้

## 4. ข้อจำกัดที่แท้จริงของวิธีนี้

**กฎนี้ต้องรอให้ agent บังเอิญผ่านด่านก่อนถึงจะเรียนรู้ได้ — และนั่นเกิดแค่ 1.0% ของคลิก**
(41 จาก 4,305 คลิก · `click-validation.md` §3)

แปลว่าในทางปฏิบัติ agent จะคลิกมั่วไปประมาณ 100 ครั้งก่อนได้หลักฐานชิ้นแรก
ซึ่งกินงบ action มหาศาลภายใต้กติกาที่นับทุก action

**`sb26` ยังเป็นตัวอย่างที่วิธีนี้ทำอะไรไม่ได้เลย** — 676 คลิกไม่ผ่านสักด่าน
ชี้ว่าบางเกมต้องการมากกว่าการคลิกสีเดียว (เช่น คลิกเป็นลำดับ หรือคลิกตามตำแหน่งสัมพัทธ์)

## 5. สถานะเทียบกับผลลบสี่ครั้งก่อนหน้า

นี่เป็น**ครั้งแรกที่วิธีของเราผ่านการตรวจกับข้อมูลจริง** — แต่ต้องอ่านให้ตรง:

| | ตรวจแล้ว | ยังไม่ตรวจ |
|---|---|---|
| กฎการให้คะแนนเลือกสีถูก | ✅ 7/7 | |
| policy เล่นเกม click จริงได้ | | ❌ **ยังไม่เคย** |
| ต้นทุนการรอหลักฐานชิ้นแรก | ✅ วัดแล้ว (~1% ของคลิก) | |

ตามแบบแผนของโครงการนี้ (`simulation-gap.md`) **การที่ชิ้นส่วนถูกต้องไม่ได้แปลว่า policy ใช้ได้**
ซึ่งเคยพิสูจน์มาแล้วกับ mapping 79% ที่ policy เล่นไม่จบสักด่าน
