# ทดสอบกับเกมจริง — และผลลบที่ทำให้ต้องเปลี่ยนวิธี

> วัดเมื่อ 14 ก.ย. 2026 · ข้อมูล: trace จริง 25 เกม จาก `example-run/` ของ `Tufalabs/duck-harness`
> ทุกตัวเลขจากการรันจริง ไม่มีการประมาณ

## 1. ทำไมต้องทดสอบนี้

ทุกอย่างก่อนหน้าวัดผลบน `mock.py` ที่**เราเขียนเอง** มันยืนยันได้แค่ว่าโค้ดสอดคล้องกับสมมติฐานของตัวเอง
ถ้าเกมจริงต่างออกไป งานทั้งหมดไม่ transfer — **นี่คือความเสี่ยงอันดับหนึ่งของโครงการ**

trace ของผู้ชนะมี board 64×64 จริง พร้อม `action_name` คู่กับ `action_display` = **เฉลย**
จึงเอามาวัดได้ว่าวิธีของเราเรียนรู้ถูกหรือไม่ โดยไม่ต้องใช้ API key

## 2. 🔴 ผลลบ: วิธีเดิมล้มเหลวเกือบสิ้นเชิง

วิธีเดิม (`effects.diff` → `sole_movement`) ต้องการให้ **มีวัตถุเดียวขยับ** จึงจะสรุปได้ว่าปุ่มทำอะไร

| | ผล |
|---|---:|
| transition ที่เป็นการเคลื่อนที่ | **2,276** |
| ที่ให้ "วัตถุเดียวขยับ" | **10 (0.4%)** |
| เกมที่กู้ทิศทางครบ 4 ทิศได้ | **1 จาก 25** |

บน mock วิธีนี้ได้ 88% แต่บนเกมจริงได้ **0.4%** — mock ง่ายเกินจริงไปมาก

### สาเหตุ

นับการเปลี่ยนแปลงต่อ 1 transition บนเกมจริง: **appeared 1,040 · moved 992 · vanished 786**

วัตถุจริง**เปลี่ยนรูปร่างระหว่างเฟรม** (sprite animate, บังกันบางส่วน, HUD เดินตลอด)
การจับคู่ด้วย hash ที่ต้องเหมือนเป๊ะจึงมองว่าวัตถุเดิม "หายไปแล้วมีตัวใหม่โผล่" แทนที่จะเป็น "ขยับ"

## 3. ✅ วิธีใหม่: centroid ของแต่ละสี

แทนที่จะจับคู่วัตถุ ให้ดู **จุดศูนย์กลางมวลของแต่ละสี**
sprite ที่ animate ระหว่างเคลื่อนที่ยังทำให้ centroid ของสีตัวเองเลื่อนไปในทิศที่ไปจริง

และเพื่อแยก HUD ออก ใช้เงื่อนไขว่า **การเลื่อนต้องขึ้นกับปุ่มที่กด** —
แถบ timer ที่เดินทุก step ไม่ว่ากดอะไร จะให้ทิศเดียวเสมอ จึงตกรอบ

| ตัวชี้วัด | วิธีเดิม | **วิธีใหม่** |
|---|---:|---:|
| mapping ที่กู้ได้ | 10 | **53** |
| ความถูกต้อง | 100% (จาก 10) | **79% (42/53)** |
| เกมที่วิธีทำงานได้ | 1/25 | **17/25** |
| เกมที่เรียนรู้ ≥3 ปุ่มและถูกหมด | 0 | **7/17** |

## 4. ✅ confidence ใช้เป็นตัวกรองได้

วิธีใหม่รายงานความมั่นใจ (ความสม่ำเสมอของผลต่อปุ่ม) ซึ่ง**ทำนายความถูกต้องได้จริง**

| เกณฑ์ confidence | เกมที่เหลือ | mapping | ความแม่น |
|---:|---:|---:|---:|
| ไม่กรอง | 17 | 53 | 79% |
| ≥0.60 | 16 | 49 | 86% |
| ≥0.65 | 14 | 43 | **91%** |
| ≥0.80 | 8 | 25 | 92% |
| ≥0.85 | 5 | 14 | **100%** |

**มีค่ามากเพราะ mapping ผิด = เสีย action ฟรี** ซึ่งคะแนน ARC-AGI-3 ลงโทษโดยตรง
agent ที่รู้ว่าตัวเอง "ยังไม่มั่นใจ" ควรกลับไปสำรวจต่อ แทนที่จะเดินตาม mapping ที่ผิด

## 6. ข้อจำกัดที่ยังเหลือ

- **8 จาก 25 เกม วิธีนี้ไม่ทำงานเลย** (ไม่มีข้อมูลพอ หรือไม่มีวัตถุที่ขยับตามปุ่ม)
  ซึ่งสอดคล้องกับที่ prompt ผู้ชนะเตือนว่า **บางเกมไม่มีตัวละครให้บังคับ**
- วัดจาก pass 0 ของแต่ละเกมเท่านั้น (ยังมีอีก 19 pass ต่อเกมที่ยังไม่ได้ใช้)
- trace เหล่านี้เกิดจาก policy ของผู้ชนะ ไม่ใช่การสำรวจอย่างเป็นระบบ
  ถ้าเราเลือกลำดับ probe เอง อาจเรียนรู้ได้เร็วกว่านี้
- ยังไม่ได้ทดสอบกับเกมสด
